负责模块：

钉钉/飞书在线表格接入

问题

1. 原有代码中第三方 API 与业务逻辑高度耦合，SDK 直接调用散布各处，字段类型转换逻辑分散，导致代码难以维护、扩展新数据源成本极高；
2. 三方接口边界条件多，之前单元测试覆盖率低，Bug 率较高。

行动

先梳理调用链路识别核心问题，设计统一数据源适配层，将第三方 API 与业务逻辑解耦；利用 TDD 模式开发，构建飞书/钉钉相关接口的测试覆盖网，降低表格相关 Bug 率。

成果

完成钉钉/飞书双数据源接入，从根本上解决数据源扩展性问题，后续接入新表格类型开发成本大幅降低；钉钉/飞书相关接口测试覆盖率达到 80%，保证后续相关模块迭代的安全性和稳定性。

SDD 规范驱动开发

  • 规范先行：OpenSpec 定义接口规范和数据模型
  • AI 协作提效：规范文档作为上下文驱动代码生成
  • 可维护性保障：结构统一，风格一致

核心认知：

TDD 是 AI 开发的质量安全网 — 约束正确性边界  |  SDD 是 AI 开发的项目规约 — 约束结构和风格

从"让 AI 帮我写代码"到"让 AI 快速、高质量地为我写代码"

持续探索 AI 编程方式，在实践中学会更好地驾驭 AI

TDD — 用测试约束正确性

先写测试划定正确性边界，再让 AI 填充实现。测试通过即交付，重构有安全网。

SDD — 用规范约束结构

OpenSpec 定义接口和数据模型，AI 基于规范生成代码，多人协作风格一致。

Skill — 用技能复用工作流程

将高频操作封装为可复用 Skill，AI 按需调用，从"写一次代码"到"沉淀一项能力"。

测试约束正确性 + 规范约束结构 + Skill 封装复用 = 让 AI 既快又稳地为我写代码
