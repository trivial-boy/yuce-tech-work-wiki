# Meeting - AI方法论、数仓与知识图谱

## Context

- 日期：2026-05-19
- 主题：Skill 开发与调试方法论、AI 时代能力重构、数据仓库架构、知识图谱、指标体系、产品架构与客户策略

## Discussion

### Skill 开发与调试方法论

- Skill 开发可按四步闭环推进：先明确目标，再规划步骤；开发和调试分别在独立窗口进行，最后另开新窗做完整验证。
- 分窗开发的核心价值是减少上下文歧义，保证开发、调试、验证三个阶段逻辑隔离。
- 成本优化的重点是把固定操作沉淀成脚本，并结合 HTML 模板复用数据，降低每次执行 Skill 时的大模型调用成本。
- 可在上线前增加预发布检查机制，由专用 Skill 检测潜在问题；部分错误可尝试自动修复，减少人工干预和算力消耗。

### AI时代的思维转变与能力重构

- 重复性工作里高频、易错的环节，应主动识别并转化为系统能力，而不是等问题出现后被动处理。
- 每个判断背后都应沉淀出可复用的思考链路和规则，而不是依赖即时感受做决策。
- 合同审核等场景适合建立规则库，通过固定原则提升一致性和效率。
- AI 对岗位替代正在加速，未来人的差异会更多体现在是否具备利用 AI 和进行抽象建模的能力。
- 企业文化上应鼓励对不合理流程持续重构，架构、代码和组织本身都应保持可迭代性。

### 数据仓库架构设计

- 三范式建模更适合金融机构等稳定性要求高、变化相对较小的场景。
- 维度建模（星型/雪花）更适合电商等变化快、分析需求强的业务环境。
- 数仓分层可按 ODS、DWD、DWS、ADS 设计：
  - ODS：原始同步层，保持与业务系统一致
  - DWD：明细清洗层，保留用户、年龄、消费金额等基础明细
  - DWS：轻度汇总层，用于减少重复关联、提升查询效率
  - ADS：应用输出层，直接面向业务报表或分析场景
- 后台可自动评估表健康度，识别冗余表并建议合并或删除。
- DWS 层可尽量自动生成，以降低人工维护成本。

### 本体论与知识图谱构建

- 实体是现实世界中的对象，如商品、订单、店铺。
- 关系是实体之间的有向连接，如“用户下单”“商品属于品类”。
- 属性是实体自身的特征，如价格、状态。
- 建模时可用横轴表达业务流程，如采购、入库、结算；纵轴表达时间、数量、责任人等维度信息，共同组成完整本体框架。
- 实际案例中，可通过知识图谱把广告投放数据与电商订单数据打通，形成跨平台全链路分析能力。

### 指标体系建设与分析

- 传统模式下汇总表过多，容易导致指标口径不一致，新增指标时需要反复对齐旧体系。
- 更好的方式是让所有原始指标都来自统一事实表，再通过维度关联和知识图谱动态组合。
- 建立标准维度后，系统可自动生成 SQL，完成指标查询与分析。
- 指标能力可进一步发布为每日自动运行任务，用于持续监控。
- 所有业务部门应基于统一指标定义协作，避免财务与业务口径冲突。

### AI能力层级与发展路径

- AI 能力可分四层演进：
  1. 日常问答与思路启发
  2. AI 编程，直接生成可执行代码
  3. 为 AI 建设基础设施，提升工程化能力
  4. 实现系统自我迭代，例如投放系统自动优化
- AI 竞争的本质不只是成本，更是资产沉淀、知识复用和迭代速度的比拼。
- 开发 Skill 时要优先思考是否具备复制性，能否从单个客户扩展到整个行业。
- 当用户不会使用产品时，不应先归因于用户，而应反思产品和基础设施是否足够友好。

### 产品架构与客户策略

- 客户可分为 KA 和 SME 两类：KA 更适合重点服务和深度方案，SME 更适合轻量模块化产品。
- 数据魔方的底层架构应支持淘宝、抖音、拼多多等多平台数据接入和标准化处理。
- 当客户新增经营平台时，理想状态是不需要改动底层逻辑，而是通过标准化接入实现一键扩展。
- 当前 AI 任务仍需在可控环境中运行，金融级或高风险场景暂不适合完全放开。
- 需要持续通过模板化和自动化降低 token 消耗和整体运营成本。

## Decisions

- Skill 开发优先采用“目标明确 -> 独立开发 -> 分窗调试 -> 新窗验证”的四步闭环。
- 固定高频操作应优先脚本化和模板化，减少重复推理成本。
- 上线前增加预发布检查机制，能自动修复的错误尽量前置处理。
- 重复工作应优先抽象为系统能力，而不是继续依赖人工记忆和手工执行。
- 指标体系应围绕统一事实表和统一口径构建，避免汇总表膨胀。
- 产品与能力设计需要优先考虑跨客户复用性、可扩展性和成本控制。


## Risks / Open Questions

- 哪些错误适合自动修复，哪些场景仍需要人工确认边界
- 旧有汇总表和历史指标口径如何平滑迁移到统一事实表体系
- 多平台接入后如何平衡标准化收益、实现复杂度和运行成本
- 高风险行业场景中，AI 自动化开放程度应如何分级控制
