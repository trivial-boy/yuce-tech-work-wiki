# Inbox 总览

## 作用

- 承接同事临时转发给我的需求、会议、草稿、灵感和待确认事项。
- 这里的内容默认是“待分流”，不是最终归档位置。

## 分流规则

- 可执行需求：转到对应 `areas/.../requirements/` 或 `projects/...`
- 会议纪要：保留在 `inbox` 或沉淀到对应 `areas` / `projects`
- 已完成草稿：归档到 `archive/work`
- 无价值空白页：删除或合并

## 处理建议

- 每天至少清一次 Inbox。
- 每条记录尽量补 `type`、`date`、`source`、`status`。
- Inbox 中不要长期堆积项目正式信息，避免重复维护。
