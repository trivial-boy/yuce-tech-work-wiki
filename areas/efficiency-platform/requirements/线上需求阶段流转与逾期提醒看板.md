# 工程效率平台新增需求：线上需求阶段流转与逾期提醒看板

## 一、需求背景

当前线上需求缺少统一的可视化看板来追踪各阶段流转情况，也缺少基于评估时效的逾期识别与提醒机制。

现状问题：

- 无法快速查看线上需求当前处于哪个阶段、各阶段有多少需求在流转
- 无法识别哪些需求已经超过产品评估时限
- 逾期需求依赖人工跟进，缺少自动提醒
- 售后、产研、实施等协同方无法及时感知逾期需求处理进展

因此，需在工程效率平台新增线上需求看板能力，并支持对逾期评估需求发送群提醒消息。

## 二、需求目标

- 提供线上需求阶段流转看板，支持查看各阶段需求数量
- 提供逾期评估需求识别能力，便于产品集中处理
- 对逾期需求自动发送群提醒到“售后&产研&实施群”
- 形成线上需求评估时效规则，统一不同优先级需求的反馈要求

## 三、需求范围

本期范围包含：

- 线上需求看板
- 线上需求阶段流转数量统计
- 逾期评估需求识别
- 逾期需求群消息提醒

本期暂不明确包含：

- 产品评估结论审批流程
- 群消息提醒后的升级催办机制
- 更复杂的 SLA 配置化能力
- 非线上需求类型的统一纳管

## 四、业务规则

### 1. 需求优先级与反馈时效

线上需求进入“待处理”后，产品需要在对应时限内完成反馈。这里的“反馈”指需求状态从“待处理”变更为“产品已确认是否要做”等非待处理状态，不要求本期内完成详细方案输出。

时效规则如下：

| 优先级 | 时效要求 | 说明 |
| --- | --- | --- |
| 紧急 | 1 个工作日内 | 需完成评估，并由产品拉群 |
| 高 | 3 个工作日内 | 产品需给出反馈 |
| 中 | 7 个工作日内 | 产品需给出反馈 |
| 低 | 15 个工作日内 | 产品需给出反馈 |

### 2. 紧急需求特殊规则

- 紧急需求除需在 1 个工作日内完成评估外，还要求产品在时限内完成拉群动作
- 若系统暂无法直接识别“是否已拉群”，本期可先按需求状态反馈时限进行逾期识别，拉群动作作为后续补充字段或流程节点建设项

### 3. 逾期定义

当线上需求处于“待处理”状态，且距进入“待处理”状态的时间已超过其优先级对应工作日时限，则判定为逾期需求。

### 4. 工作日口径

建议按公司工作日历计算工作日，排除周末及法定节假日。若当前平台暂无统一工作日日历，本期可先明确为：

- 方案 A：先按自然日近似计算，后续升级为工作日
- 方案 B：接入公司工作日日历，直接按工作日计算

优先建议采用方案 B，避免逾期判断偏差。

## 五、功能设计

### 1. 线上需求阶段流转看板

看板需支持展示线上需求在各阶段的数量统计，帮助查看需求整体流转情况。

建议至少展示以下内容：

- 待处理数量
- 产品评估中数量
- 已确认要做数量
- 已确认不做数量
- 其他业务已定义阶段数量
- 逾期需求数量

建议支持的筛选维度：

- 时间范围
- 产品线
- 优先级
- 需求来源
- 负责人

建议支持点击数量下钻到需求明细列表。

### 2. 逾期评估需求列表

新增逾期需求视图，至少包含以下字段：

- 需求标题
- 需求编号
- 优先级
- 当前状态
- 进入待处理时间
- 已停留时长
- 逾期天数或逾期工作日
- 产品负责人
- 需求来源方

建议支持：

- 按优先级筛选
- 按是否逾期筛选
- 按产品负责人筛选
- 批量提醒

### 3. 群提醒能力

对于已逾期且仍处于“待处理”状态的线上需求，系统支持发送提醒消息到“售后&产研&实施群”。

提醒方式建议包含：

- 定时任务自动提醒
- 列表页手动批量提醒

提醒对象：

- 售后&产研&实施群

消息触发建议：

- 首次逾期时自动提醒一次
- 逾期后每日固定时间继续提醒，直到需求状态从“待处理”变更为其他状态
- 手动批量提醒不受自动提醒限制，但需记录操作人和时间

### 4. 提醒消息文案建议

可参考如下文案：

```text
【线上需求逾期提醒】
以下线上需求已超过产品评估时限，请相关负责人尽快处理：
1. 需求标题：xxx，优先级：高，待处理时长：4 个工作日
2. 需求标题：xxx，优先级：中，待处理时长：8 个工作日
请产品侧尽快确认是否处理，并同步进展。
```

若后续支持 @具体负责人，可进一步提升提醒效果。

## 六、状态流转口径建议

为保证统计与逾期判断一致，需明确线上需求的状态口径。建议至少包括：

- 待处理
- 产品评估中
- 已确认要做
- 已确认不做
- 已转排期
- 已关闭

本需求中的“已反馈”定义为：

- 需求状态从“待处理”流转到上述任一非“待处理”状态

## 七、核心统计指标

建议看板展示以下指标：

- 线上需求总数
- 各阶段需求数
- 当前逾期需求数
- 各优先级逾期需求数
- 平均待处理时长
- 按产品负责人维度的待处理/逾期分布

## 八、实现建议

### 1. 数据来源

- 线上需求基础数据
- 需求优先级
- 当前状态
- 状态变更记录或进入待处理时间
- 产品负责人

其中，逾期计算依赖“进入待处理时间”，如当前系统未直接保存，需从状态流转记录中反推或新增字段沉淀。

### 2. 关键实现点

- 统一线上需求状态枚举
- 明确“进入待处理时间”的取值来源
- 计算工作日时长
- 标记是否逾期
- 支持提醒发送记录，避免重复无效轰炸

### 3. 提醒记录建议

建议新增提醒记录字段或表，记录：

- 需求 ID
- 提醒时间
- 提醒方式
- 提醒批次
- 是否自动提醒
- 操作人

用于后续追踪提醒效果和避免重复发送。

## 九、验收标准

### 1. 看板验收

- 可查看线上需求各阶段流转数量
- 可查看逾期需求数量
- 可按筛选条件查看对应统计结果
- 可下钻到逾期需求明细

### 2. 逾期判断验收

- 系统可根据需求优先级识别是否逾期
- 当需求状态仍为“待处理”且超出对应时限时，正确标记为逾期
- 当需求状态变更为非“待处理”状态后，不再标记为逾期

### 3. 消息提醒验收

- 系统可对逾期需求发送群提醒
- 群提醒对象为“售后&产研&实施群”
- 需求处理后不再继续提醒
- 支持手动触发批量提醒

## 十、待确认事项

- 线上需求当前完整状态枚举是什么
- “产品拉群”动作是否已有字段或流程记录可识别
- 工作日是按公司日历还是先按自然日计算
- 群消息是走钉钉机器人、群 webhook，还是已有消息中心能力
- 是否需要区分首次提醒、每日提醒、升级提醒
- 看板是否只看当前存量，还是也要看一段时间内的流转趋势

## 十一、结论

本次需求本质上包含两部分能力建设：

- 面向管理视角的线上需求阶段流转看板
- 面向协同催办的逾期评估识别与群提醒能力

建议先完成最小可用版本：

1. 打通线上需求状态数据
2. 支持按优先级识别逾期
3. 提供逾期需求列表
4. 支持群消息自动/手动提醒
5. 在看板中展示各阶段数量和逾期数量

后续再逐步补齐工作日日历、提醒升级策略、负责人 @能力和更完整的趋势分析。
