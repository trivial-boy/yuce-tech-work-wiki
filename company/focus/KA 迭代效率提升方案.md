迭代流程sop

1. **需求预评审&排期**
- **产品确认**  需求提出后， 产品进行第一轮确认，如果确认是合理且有效的需求，流转为 `产品已确认` 节点，转到 `开发负责人` 。其他情况流转为 `优先级低` 或者 `拒绝`
- **产品排期**  产品根据 开发评估和 估时，对需求进行排期或者拒绝。状态流转为 `需求已排期` 或 `拒绝` 如果需求进入排期状态，则需要在对应的 KA 迭代项目中建对应需求的工作项并在工程效率平台关联迭代，将需求关联到对应工作项，状态置为`待处理`

1.  **需求设计&评审**
- **产品prd 设计** 需求进入开始迭代后，产品出具prd 文档。完成后，状态流转为 `产品prd评审`
- **产品prd 评审**  产品负责人、开发、 ui、运维 共同进行评审。评审通过后，状态根据情况 流转为 `ui 设计` 或者 `技术设计`，负责人设置为 ui 负责人 或者 技术负责人
- **ui 设计**  ui 根据 产品prd 文档 出具 ui 设计稿。 完成后，状态流转为 `ui 评审` 
- **ui 评审**  ui 拉上 产品、技术、运维 共同评审。通过后，状态流转为 `技术设计`，负责人设置 对应开发负责人
- **技术设计**  开发负责人根据 prd 文档 设计 。通过后，状态流转为 `技术评审`
- **技术评审**  开发负责人根据 prd 文档 设计 。通过后，状态流转为 `开发中`
1. **开发、测试& 出包**
- **开发**  开发进行开发。交付产物为 经过冒烟测试的制品。通过后状态流转为 `已提测`
- **测试**  测试统一收集 `已提测` 的需求，在工程效率平台，发起提测单，对`已提测`进行测试, 一批测试都通过后，填写对应测试的制品。每一个需求测试通过后都需要将状态置为测试通过，状态流转为 `待`
- **验收** 测试完成之后
- **发布**  当迭代中所有测试都通过后，开放将并代码到release，测试重新打制品包，将工程效率平台修改迭代状态为 测试完成已出包。
